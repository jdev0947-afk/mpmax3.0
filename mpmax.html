MPMAX

Conecta o banco

O MPMAX guarda tudo no teu Supabase. Cola a URL do projeto e a chave anon pra começar.

Serve a nova (sb_publishable_...) ou a antiga (eyJ...). Nunca a service_role. A service_role ignora RLS e daria poder total sobre o banco a quem abrisse este arquivo.

Se ainda não criou o projeto
1Cria um projeto no Supabase, região South America (São Paulo).
2No SQL Editor, roda o script mpmax-supabase.sql inteiro.
3Em Project Settings → API, copia a Project URL e a chave anon.

    Banco de dados
    
      
    Todos os dados e prints ficam no teu projeto Supabase. Este navegador guarda apenas a URL e a chave para saber qual projeto abrir.
    
      
    
        
    
          
          
        
    
        
    
          
          
          Esta chave fica salva em texto puro neste navegador e viaja no código da página. Ela não é segredo — quem protege as tabelas é a RLS. Nunca a service_role aqui.
        
    
      
    
      
    
        
        
        
      
    
      
    Estes campos estão travados porque as credenciais vêm fixas do mpmax.js, no bloco CONFIG do topo do arquivo. Para mudar de projeto, edita lá — ou esvazia o CONFIG para voltar a configurar por esta tela.
    
      
    
    
    

    
    
      
    Cópia de segurança
    
      
    O Supabase já faz backup do projeto, mas uma cópia tua não custa nada. O JSON carrega leads, toques e tarefas; os prints continuam no bucket e entram aqui só como referência.
    
      
    
        
        
        
        
        
      
    
      
    Sair encerra a sessão e volta pro login. Desconectar apaga também a URL e a chave guardadas aqui. Nada é removido do Supabase em nenhum dos dois casos.
    
    
    

    
    
      
    Alertas do sistema
    
      
    Com a permissão ligada, uma tarefa que vence aparece como notificação do sistema mesmo com a aba em segundo plano. Sem ela, o aviso só aparece dentro do app.
